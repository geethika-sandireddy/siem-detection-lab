# T1021.001 — Remote Services: Remote Desktop Protocol

**Victim:** Windows 10, RDP enabled (host-only network only — never exposed
externally, this was purely to generate the log pattern).

## Atomic test used

Atomic Red Team's T1021.001 atomics are mostly about *enabling* RDP or
*discovering* RDP sessions rather than performing a full logon, so the
actual RDP connection itself was simulated directly: a second lab VM on the
same host-only network connected via `mstsc.exe` to the Windows victim
using a valid low-privilege test account, followed by one deliberate failed
attempt with a wrong password first.

## What showed up in Wazuh

- **Event ID 4624** (successful logon) with `LogonType = 10`
  (RemoteInteractive) — this is the specific field that distinguishes an
  RDP logon from a console/network logon.
- **Event ID 4625** (failed logon) with `LogonType = 10` for the wrong-password
  attempt first.
- **Event ID 1149** (`Microsoft-Windows-TerminalServices-RemoteConnectionManager`)
  — fires specifically for RDP, at the network-connection stage, slightly
  before the 4624 authentication result.

## Rule test result

| Rule | Fired? | Notes |
|------|--------|-------|
| `100050` (any RDP logon) | ✅ | Fired on the successful connection, LogonType 10 confirmed |
| `100051` (off-hours RDP) | ⚠️ untestable as-is | Test was run during the day; logic verified by temporarily shrinking the `<time>` window to include "now" rather than actually waiting until night — legitimate for confirming rule syntax, but **not** the same as a real off-hours observation, noted honestly here rather than claimed as a clean pass |
| `100052` (failed RDP logon) | ✅ | Fired on the deliberate wrong-password attempt |

**Verdict: caught**, with one asterisk — `100051` was syntax-tested, not
behavior-tested under real off-hours conditions, and that distinction is
worth keeping visible rather than rounding up to a full pass.
