# T1003.001 — OS Credential Dumping: LSASS Memory

**Victim:** Windows 10.

## Atomic test used

```powershell
Invoke-AtomicTest T1003.001 -TestNumbers 1
```

This atomic uses `comsvcs.dll`'s `MiniDump` export (via `rundll32.exe`) to
dump the LSASS process memory to disk — one of the classic "living off the
land" LSASS-dumping methods, avoiding a dropped copy of Mimikatz entirely.

```
rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump <lsass PID> lsass.dmp full
```

## What showed up in Wazuh

**Sysmon Event ID 10** (ProcessAccess) is the key log source: it records
when one process requests a memory-read handle into another. The atomic
run showed `rundll32.exe` requesting access into `lsass.exe` with a
`GrantedAccess` value of `0x1410` (PROCESS_QUERY_LIMITED_INFORMATION |
PROCESS_VM_READ) — the specific access-rights combination LSASS dumping
tools request.

Also visible: **Sysmon Event ID 1** for the `rundll32.exe` launch itself,
with `comsvcs.dll,MiniDump` in the command line/arguments.
