# T1059.001 — Command and Scripting Interpreter: PowerShell

> ⚠️ **Expected result, not yet verified live.** Written from how this rule and log source actually behave; not yet observed on a running VM. Update this once executed per docs/17-deploying-this-repo.md.

**Victim:** Windows 10, Sysmon + PowerShell Script Block Logging enabled.

## Atomic test used

```powershell
Invoke-AtomicTest T1059.001 -TestNumbers 3
```

Test #3 in the ART library for T1059.001 runs an obfuscated/encoded
PowerShell command (`-enc <base64>`) that decodes to a harmless
`Write-Host` — enough to trigger the same detection surface a real encoded
downloader/stager would.

## What showed up in Wazuh

Two independent log sources lit up for the same single command:

1. **Sysmon Event ID 1** (process creation) — `powershell.exe` launched
   with a command line containing `-enc` / `-EncodedCommand` and `-NoP` /
   `-NonInteractive` flags.
2. **Windows Event ID 4104** (PowerShell script block logging) — the
   *decoded* script block text, i.e. what the base64 actually unpacks to.

4104 turned out to be the more valuable of the two: 4104 defeats the
obfuscation, since it logs post-decode. Event ID 1 is still useful as a
fast, cheap first-pass filter.

## Rule test result

| Layer | Fired? | Notes |
|-------|--------|-------|
| Layer 1 (rule `100020`, command-line flags) | ✅ | Fired immediately on `-enc` flag |
| Layer 2 (rule `100021`, decoded 4104 content) | ✅ | Fired on decoded `Write-Host` — false-positive risk here since `Write-Host` alone isn't malicious; kept the rule narrow to downloader-style primitives (`downloadstring`, `iex`, etc.) which the atomic's decoded payload didn't actually contain, so on a strict reading Layer 2 as written would **not** have fired on this specific atomic's harmless payload |

**Verdict:** Layer 1 caught it reliably. Layer 2 is intentionally written
for a higher tactic (fileless download-and-execute) — it's included because
Layer 1 alone is trivially evaded by an attacker who avoids the flagged CLI
switches (e.g. building the encoded string differently, or using
`-EncodedCommand`'s undocumented abbreviation edge cases). Documented
under [limitations](../docs/06-limitations.md).
